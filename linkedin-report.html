先看结论

它的价值在于企业发现与画像，时间维度仍是短板。

这份表适合作为企业检索、实体匹配和研究候选池的基础。当前版本不具备可靠的采集时间和历史序列，无法直接支持增长跟踪或交易信号检验。

覆盖很广，分布并不均衡

美国占全部页面 39.33%，在国家字段非空的记录中占 50.84%。22.64% 的记录缺少国家。国家排名反映数据集覆盖结构，不是全球企业数量排名。

典型页面远小于平均值

关联成员中位数为 3，平均值为 64.5；关注数中位数为 27，平均值达 2,162.8。头部页面显著拉高均值。

结构可用，口径需要治理

ID、LinkedIn 链接和平台标识全部唯一，但页面混有学校与展示页，行业标签存在新旧命名；专业领域字段全部使用非 JSON 表达。

先补时间，再讨论动态

创建与更新时间全部为默认纪元时间。融资对象仅覆盖 1.63%。没有融资数据或关注度低，都不能直接推断企业经营状态。

范围提示：本报告中的“页面”是数据库记录；“company 类型”是平台页面分类，不代表经过工商核验的独立法人。除明确注明外，分母均为 3,906,160 条页面记录。

六个会改变分析结果的问题

  1. 页面类型不等于法人类型。company 为 3,780,925 条（96.79%），showcase 为 82,793 条，school 为 17,222 条，空类型为 25,220 条。企业候选池应先限定 company，不能把所有页面直接称为公司。
  2. 唯一 ID 不保证实体去重。非空名称经去首尾空格、转小写后有 32,345 个重名组，组内超出首条的记录共 45,063 条；最大组达 696 条。重名可能来自同名公司、分支或其他情况，不能直接删除。应结合官网域名、地区、平台标识及母子公司关系核验。
  3. 网址有值不等于可访问。官网字段非空但 ClickHouse domain() 无法提取主机名的有 13,227 条。缺少协议、格式特殊或无效字符串均可能造成该现象。本次没有逐个访问官网，不能据此报告网站存活率。
  4. 总部对象完整度存在层级差异。对象非空为 3,034,220 条，国家非空为 3,021,969 条，城市非空为 2,594,636 条；只用对象非空判断地理可用性，会高估覆盖。
  5. 专业领域不能按 JSON 数组直接解析。1,857,096 条非空记录全部不能通过 JSON 校验；格式样本呈现类似 PostgreSQL 数组字面量的花括号、引号和逗号结构。分隔符可能位于引号内，应使用兼容转义的解析器，不能简单按逗号拆分。
  6. 时间戳没有信息量。全部创建与更新时间为 1970-01-01 08:00:00（数据库输出时区下的纪元默认值）。不可解释为成立时间、抓取日期或最新更新日期。
优先级判断：先恢复来源版本、采集时间和字段语义，再做页面类型过滤、实体解析与行业标准化。先扩充标签数量，并不能解决数据是否可比较的问题。

地区结构：美国集中，未知地区不能忽略

美国共有 1,536,390 条页面，是英国 268,683 条的约 5.72 倍。美国、英国、荷兰合计占全表 49.57%。中国（CN）只有 22,590 条，占 0.58%；这一比例不能用于判断中国企业在全球经济中的比重。

缺少国家的 884,191 条页面中，关联成员中位数为 1、关注数中位数为 11，低于全表的 3 和 27。这说明缺失组在这些可观测指标上并非与其他记录完全相同；直接删除未知地区，会改变样本结构。

应用含义：做跨国比较时，应同时给出“全表占比”和“已知国家内占比”，并在国家内部比较行业与规模。对中国企业检索，应增加其他来源补全，而不是把本表当作企业总体名录。

代码格式检查发现 1 条非空国家值不满足两位英文字母规则。其余两位代码也未逐一校验为现行 ISO 国家/地区码，因此不报告“覆盖多少个国家”。总部字段不等于营收地区、客户地区或注册地。

行业探索：标签混用，会分散同一赛道

行业有效覆盖率为 96.61%，共有 523 个非空原始标签。最大标签 Information Technology & Services 有 205,894 条（5.27%），其次为建筑 147,678 条和营销广告 138,215 条。

同一表中同时出现 Computer Software 与 Software Development、Information Technology & Services 与 IT Services and IT Consulting 等标签。它们提示分类体系可能混用，但未经定义核对不能直接认为完全等价。排名应保留原始标签，同时另建有版本号的标准行业映射。

地区内部的行业结构，比全局排名更具体

美国的最大行业标签是 Construction（89,347 条），占美国页面约 5.82%；中国的最大标签是 Appliances, Electrical, and Electronics Manufacturing（1,047 条），占中国页面约 4.63%。中国前列还包括电子制造、机械制造和工业机械制造，体现这份样本中的制造业方向。由于标签拆分和平台覆盖偏差，这不能推出两国真实产业构成。

检索策略：初筛采用同义标签集合，提高召回；分析阶段使用经审核的行业映射，记录一对多与不确定映射。语义分类可以补充空标签，但模型预测需与原始标签分开保存。

按关注数降序取前 39,062 条（向上取整的约 1%），关注数合计约 59.20 亿，占全部页面关注数加总的 70.07%。这里的加总会重复计算同时关注多个页面的人，不是独立用户数。

0–10 个关联成员的页面共 2,881,715 条，占 73.77%。超过 1,000 个关联成员的页面仅 31,994 条（0.82%），却贡献约 55.22% 的关注数加总。单用均值描述企业规模，会弱化绝大多数页面的实际分布。

“关注多”不等于“增长快”

全表 log(1+关注数) 与 log(1+关联成员数) 的 Pearson 相关系数为 0.771，显示两者在横截面上存在较强正相关。这不能识别因果关系，也不能证明关注数可预测未来经营或收益。应在同国家、同行业、相近规模内计算分位数，避免把大公司天然的曝光优势当成异常信号。

记录为已验证的页面只有 145,225 条（3.72%），其关联成员中位数为 252，未验证组为 3；关注中位数分别为 8,055 和 24。若仅使用已验证页面，将明显偏向规模较大、关注较高的页面。该字段也不等于工商存续认证。

数据处理注意：671,772 条页面有关注数但关联成员为零；102,350 条有成员但关注数为零。关注数/成员数比率必须设置零值规则，且低分母组应单独处理，不能直接生成“优质公司排行榜”。

融资信息：适合补充检索，不足以估算整体融资率

融资对象非空仅 63,628 条（1.63%）。这些对象包含轮次、最近融资、来源链接及更新时间等键，但对象存在并不代表金额、币种和事件日期完整；本报告不汇总融资金额、不推算估值。

企业研究：建立可核验的候选池

逐步限定有效名称与行业、可解析的两位国家代码、非空描述和可提取主机名的官网，全表得到 2,172,141 条初筛记录。进一步限定 company_type='company'，保留 2,123,521 条；再要求关联成员在 11–200 之间，得到 692,257 条公司页面，占 company 类型页面的 18.31%。

交易研究：当前先做实体基础层

本表没有价格、成交、财务报表、证券代码和可用的历史采集时间，不能直接构建或验证投资策略。一个合理的后续研究路径是：公司页面映射到证券实体，保留映射置信度与生效时间；定期保存不可覆盖的快照；仅使用决策时已获得的数据构造变化特征，再独立检验其增量信息。

任何后续实证都要将“字段所描述事件的时间”与“研究者首次获得数据的时间”分开。当前静态页面不能倒填到历史时点，否则会产生前视信息。这里讨论的是数据可用性，不作具体证券或买卖建议。

建议的工程落地顺序

  1. 恢复时间与来源：补采集时间、来源版本、原始对象校验值；把已知默认时间转换成有原因标签的缺失状态。
  2. 建立标准层：提取国家、城市、成立年；解析专业领域；规范网址；保留 raw 值与转换版本。
  3. 分开页面与实体：维护 page_id 与 entity_id，保留同名、分支、集团等关系，采用人工核验闭环。
  4. 构建应用指标：按地区×行业×规模提供覆盖率、缺失率和分位数，避免直接输出单一“企业评分”。
  5. 建立时间序列：在数据源允许的更新方式下保存快照，监控新增、失联、字段变化和抽样准确率。

方法、口径与可复现性

本报告直接查询用户提供的 LinkedIn 公司数据表，分析日期为 2026-11-19（北京时间）。全部主要统计来自全表 SQL 聚合；结构样本只用于识别嵌套字段格式，不参与比例估计。报告不包含企业级明细、内部连接信息或访问凭据。

  • 统计单位：一行一个平台页面，N=3,906,160；ID、LinkedIn 链接和平台标识的唯一数均为 N。标签 company、school、showcase 原样保留，company 仍可能包含非营利组织等。
  • 缺失规则：字段覆盖率将去空格并转小写后的空字符串、null、none、n/a、[]、{} 视为缺失。名称缺失为 1,283 条，其中严格空字符串为 930 条。基于严格非空字符串的专项审计会另行说明，不与覆盖率口径混淆。
  • 数量字段：分位数使用 ClickHouse quantilesExact/quantileExact，全表计算包含零值；均值为算术平均。数量字段为无符号非 Nullable 类型，零不保证是业务真实零。
  • 国家：从总部对象提取 country 后去首尾空格并转大写。已知国家分母为 3,021,969，包含 1 条格式异常值；两位格式通过不代表 ISO 代码有效。
  • 行业：按原始标签去首尾空格汇总，不自动合并近义标签；探索表展示页面数≥1,000的非空行业。中英文显示名仅作辅助，原标签随表保留。
  • 关联与集中度：相关性使用 log1p 后的 Pearson 系数；关注集中度将页面关注数相加，会重复计算跨页面用户，不能解释为独立人群。
  • 时间：成立年采用 JSONExtractInt；零包含缺失或无法提取的情况。1800–2026 为审查区间，实际数据新鲜度无法确认；分析日不等于数据观测日。
  • 抽样与不确定性：这是给定表的全量描述，不是全球企业的概率抽样。全量计算不能消除来源偏差；不报告全球推断的置信区间，也不把相关性表述为因果效应。
  • 一致性：国家、行业、规模与年份分组分别加总回全表。查询是分次只读聚合，不是跨语句事务快照；发布前再次检查总行数与 ID 唯一数。
查看核心 SQL 口径（示意表名 company_pages）
-- 全表规模与唯一性
SELECT count(), uniqExact(id) FROM company_pages;

-- 国家分布
SELECT upperUTF8(trimBoth(JSONExtractString(headquarter, 'country'))) AS country,
       count() AS pages
FROM company_pages GROUP BY country ORDER BY pages DESC;

       quantilesExact(0.5, 0.9, 0.99)(associated_members_count),
       corr(log1p(followers_count), log1p(associated_members_count))
FROM company_pages;
